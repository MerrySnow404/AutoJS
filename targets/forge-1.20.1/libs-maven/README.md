# libs-maven — local stand-ins for artifacts this machine cannot fetch

This directory is **not** a mod dependency and nothing in it is shipped. It exists
so this target can be built on a machine that cannot reach `maven.neoforged.net`,
and it is only ever consulted when the build is given `-Pautojs.localToolchain`.
Without that flag the build resolves everything from the real repositories and
this directory is ignored.

## What is in it

### `net/neoforged/minecraft-dependencies/1.20.1/` — generated

A metadata-only Gradle module (no artifacts): the same thing the ModDevGradle
LegacyForge plugin injects into the `net.minecraftforge:forge` component as the
source of Minecraft's library list. The real one is published only on
`maven.neoforged.net`, and it is the one artifact this target's dependency graph
needs that nothing reachable serves: `maven.minecraftforge.net` serves the Forge
userdev jar and `de.oceanlabs.mcp:mcp_config:1.20.1`, but has no `net/neoforged`
path at all. Without it, dependency resolution fails before anything is compiled.

It was generated by `gen-minecraft-dependencies.py`, from the two things Mojang
publishes — both reachable — namely the client version manifest and the server
bundle's `META-INF/libraries/**`. The generation rule was derived from the
authoritative module Gradle had already cached for Minecraft 1.19.2, and the
script **reproduces that file exactly** (order-insensitive; all seven variants,
every dependency, attribute and capability). Run it with `--verify-against` to
re-check that claim:

```sh
python gen-minecraft-dependencies.py --mc 1.19.2 \
  --client-manifest <…>/minecraft_1.19.2_version_manifest.json \
  --server-jar      <…>/minecraft_1.19.2_server.jar \
  --verify-against  <…>/minecraft-dependencies-1.19.2.module
```

Applied to the 1.20.1 inputs it produced the file here. 1.20.1's manifest has the
same shape as 1.19.2's (88 libraries, the same three rule shapes, no multi-rule
library, no OS-gated library without a classifier, 44 classifier-free libraries,
29 bundled server libraries), so the result has the same variant counts as the
verified 1.19.2 one: 44/44/29/29 libraries plus 21/15/9 natives.

**Residual risk, stated plainly:** there is no ground-truth 1.20.1 module to
compare against, because it cannot be downloaded here. This file is a faithful
reproduction of a derived artifact, not the artifact itself.

### `dev/latvian/mods/` — the published files, fetched out of band

`rhino`, `rhino-forge` and `kubejs-forge` on the KubeJS 2001 generation, with the
poms and module metadata `maven.latvian.dev` serves. These are unmodified
published artifacts; they are here because Gradle's own HTTP client is reset by
that host from this machine (`Connection reset` on every GET) while `curl` reads
the same URLs without trouble. Nothing was generated or edited.

## Regenerating

The KubeJS artifacts are a plain download of
`https://maven.latvian.dev/releases/dev/latvian/mods/<module>/<version>/<module>-<version>.{jar,pom,module}`.

The `minecraft-dependencies` rule is four sentences, all of them in
`gen-minecraft-dependencies.py`:

* `clientCompileDependencies` = the client manifest libraries whose name has no
  classifier;
* `clientRuntimeDependencies` = the client manifest libraries with no rule at
  all, plus one dependency requesting the `minecraft-dependencies-natives`
  capability, which is what makes Gradle pick a natives variant;
* `serverCompileDependencies` / `serverRuntimeDependencies` = the libraries
  bundled in the server jar's `META-INF/libraries`;
* the three `client*Natives` variants = the client manifest libraries gated on one
  operating system, grouped by it, capability `minecraft-dependencies-natives`.
